Основа: `staging`, `7c7b307`. Версия модуля сохранена: **17.0.2.62**.

**Enterprise-совместимость пока не подтверждена, новые Enterprise-провайдеры
не разрешены.** Локально нет исходников Enterprise и подключения к Odoo shell
`odoo17-vataga-staging`. Официальный `odoo/enterprise` недоступен через
подключённый GitHub и Git. Список установленных модулей и repr верхнего метода
не устанавливают ни полную MRO, ни реально исполняемую цепочку `super()`.

## Выполнено

- Ошибка провайдера теперь называет все неизвестные определения: класс в
  реестре, модуль функции и qualname. Проверка по идентичности функций сохранена.
- Ссылки на проверенные Community-функции захватываются при импорте адаптера.
  Последующее переопределение исходного класса не становится разрешённым
  автоматически из-за повторного чтения изменённого атрибута этого класса.
- Добавлен приватный отчёт `_native_partial_cost_provider_report()` для
  администратора с проверкой точного имени базы. Он читает все определения
  методов в MRO, цепочки `__wrapped__`, файлы, строки, исходники и SHA-256.
  Дополнительно показывает определения полей cost/employee/duration и их
  compute-методы/зависимости из уже построенного реестра. Отчёт не вызывает
  расчёт стоимости, Stock или создание fixture.
- SHA-256 служит для сравнения сборок, а не для автоматического разрешения
  неизвестного кода. Порядок определений в MRO сам по себе не доказывает, что
  каждый override вызывает `super()`.
- Сохранены прежние защиты старых интервалов, ставок, Stock/SVL и checkpoint.
  Формулы расчёта, cumulative-minus-booked и капитализация не заменялись.

Фактическая Community-цепочка определений и вызовов после просмотра исходников:

```text
mrp.production._cal_price:
  NativePartialProduction
  -> mrp_account.models.mrp_production.MrpProduction
  -> mrp.models.mrp_production.MrpProduction

mrp.workorder._cal_cost:
  NativePartialWorkorder
  -> mrp.models.mrp_workorder.MrpWorkorder
```

`mrp_account._cal_price` вызывает `_cal_cost` каждой WO и добавляет стоимость
компонентов и `extra_cost * quantity`. Community `_cal_cost` объединяет
перекрывающиеся интервалы WO и умножает длительность объединения в часах на
`workcenter.costs_hour`. Поэтому сумма длительностей отдельных перекрывающихся
строк не является правильным ожидаемым результатом этого провайдера.

Подтверждены:

| Сценарий | Реальная стоимость готового выпуска |
| --- | --- |
| Исходный 4/5, затем 1/5 с новой работой | **140 + 35 = 175** |
| Два перекрывающихся интервала одного WC, затем новая работа | **140 + 35 = 175**, перекрытие не считается дважды |
| Два WC: 60/час × 60 минут и 30/час × 30 минут; затем по 15 минут каждого | **155 + 42.5 = 197.5**; checkpoint каждого WC: 60→75 и 15→22.5 |
| Неизвестный `_cal_price` или `_cal_cost` | Отказ до Stock; снимок не меняется |
| Функция с именем `mrp_workorder_hr_account...MrpWorkorder._cal_cost` | Отказ: совпадение имени не разрешает функцию |
| Изменённый Community `_cal_cost` ниже верхнего адаптера | Видим в MRO, отказ до Stock |
| Отчёт и исходники провайдеров | Полная MRO, без изменений Stock/checkpoint; только администратору и в указанной базе |

Тест с названием employee extension проверяет **отказ неизвестному коду**.
Он **не является регрессией Enterprise-расчёта затрат сотрудников**.

## Получение фактических Enterprise-исходников

Вариант без обновления модуля: запустить файл
`scripts/inspect_cost_provider_shell.py` в Odoo shell той же staging-службы,
с её реальными config/addons paths:

```sh
odoo shell --no-http -d odoo17-vataga-staging < extra-addons/quality_vataga/scripts/inspect_cost_provider_shell.py > /tmp/vataga-cost-providers.json
```

Этот скрипт работает и на `7c7b307`: новые методы модуля ему не нужны.
Он экспортирует определения `_cal_price`/`_cal_cost`, их исходники и полные
Python-файлы провайдеров, чтобы проверить импортированные helpers и другие
переопределения. В отчёте нет строк сотрудников или их ставок.
Следует передать полученный JSON для дальнейшего анализа. Если файл провайдера
вызывает helper из другого модуля, потребуется также исходник этого helper.

Вариант после доставки кода и restart: временная Scheduled Action с кодом
`scripts/cost_provider_scheduled_action.py`. Дополнительных таблиц эта
диагностика не добавляет. Полный сценарий выпуска до анализа отчёта снова
остановится на защите провайдера.

## Оставшаяся Enterprise-проверка

1. Получить фактические определения и их исходники из staging. Установить
   вызовы `super()` и все дополнительные входы расчёта: поля WO/WC, сотрудники,
   ставки, интервалы, фильтры потерь, fallback и любые побочные записи.
2. Если Enterprise `_cal_price` добавляет стоимость в обход адаптированного
   `_cal_cost`, текущий checkpoint её не покрывает. Такой провайдер нельзя
   просто добавить в список. Сначала нужен проверенный отдельный путь delta.
3. Если `_cal_cost` включает сотрудников, расширить basis и запреты изменения
   по **фактически используемым** полям, связям и ставкам. Сравнение только
   числовой суммы недостаточно: изменение старого входа с компенсирующей новой
   работой также должно отклоняться. Старый checkpoint без нужного basis не
   должен приниматься молча.
4. На одноразовой Enterprise-базе добавить регрессии: ненулевая стоимость WC;
   один и два сотрудника с разными ненулевыми ставками; параллельные интервалы;
   новая работа после первого выпуска; изменение/переназначение/удаление старых
   интервалов и ставок; изменение расчётных полей; компенсирующее изменение
   старой работы; rollback после реального Stock и checkpoint. Ожидаемые суммы
   должны следовать из проверенного Enterprise-алгоритма.
5. Только после успешных реальных тестов разрешить конкретные реализации
   провайдеров. Сохранить отказ всем остальным. Повторить Community-набор.
6. Повторить существующий rollback-only QUNIT probe (`none`, затем `lot`),
   `quality_partial_release` и прежние Enterprise-регрессии. Для PASS необходимы
   фактические `result=PASS, rollback=COMPLETE`, а не наличие файлов тестов.

На момент этого изменения пункты 1–6 Enterprise-проверки **не выполнены**.
Версия `.63`, пользовательская кнопка и готовность интеграции не объявляются.
