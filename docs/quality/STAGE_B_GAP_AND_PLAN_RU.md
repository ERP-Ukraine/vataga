# Этап B: GAP и архитектура безопасного частичного выпуска

База анализа: quality_vataga 17.0.2.53, staging. Решения пользователя 22.11.2026 включены в план: выпуск только после завершения всех обязательных проверок; serial сопоставляется по подтверждённому серийному номеру; номера строк разных QC не являются идентичностью изделия; при нескольких матрицах без устойчивой идентификации частичный выпуск запрещён, полный PASS остаётся допустимым. Пользователь разрешил реализацию безопасного варианта на staging.

## Существующее поведение

| Узел | Реализация | GAP |
|---|---|---|
| Фактическая выработка | mrp_quality_quarantine.py: set_qty_producing, _post_inventory; quality_check.py: _get_in_process_sample_quantity, _get_in_process_registration_quantity | Есть факт/лот и проведённые строки, но нет отдельного snapshot количественного распределения |
| Shop Floor / регистрация | mrp.workorder verify_quality_checks/pre_record_production и существующие JS-компоненты | Сохраняются без изменения |
| Матрица | quality.check.sample: sample_result, is_complete, has_failure, история; автоматическое число по факту | sample_number локален внутри QC. Межоперационной физической идентичности строки нет |
| Полный PASS | _quality_covered требует все обязательные QCP и PASS всей матрицы по каждому lot; _quality_release_if_passed | Рабочий механизм полного выпуска есть |
| Частичный FAIL | QC становится FAIL, весь выпуск остаётся в производственном карантине | Требуется разрешить только доказанное годное количество |
| Полный FAIL / pending | Полный выпуск запрещён | Сохранить; не выпускать даже PASS-строки, пока не закрыт обязательный набор проверок |
| Склад | _quality_prepare_release создаёт один draft move на проведённый stock.move; quality_single_release UNIQUE(quality_held_move_id) | Нельзя бездумно дробить этот move на несколько связанных выпусков или снимать ограничение уникальности |
| Исполнение | _quality_complete_release копирует ВСЕ фактические строки источника | Передача planned quantity=3 этому методу всё равно может переместить исходные 5. Для частичного пути нужен отдельный ограниченный исполнитель |
| Техсовет | _get_board_batch/_prepare_board_quarantine_approval/_check_board_batch_stock рассчитаны на целую удержанную партию | Существующие производственные решения сохраняются. Остаток после частичного выпуска не должен ошибочно исполняться как исходная полная партия |

## Граница первой версии B

Отдельный явный признак на тестовом товаре. Snapshot включения фиксируется только в новых MO на CAB с существующим производственным карантином. Старые MO, реальные товары, другие склады, входной контроль, регистрация выработки и Shop Floor не включаются автоматически. Тип отслеживания товара не меняется.

Одна атомарная операция распределения на фактически проведённый MO. Если в его проведённом выпуске несколько партий, каждая проверяется по собственному lot; до завершения полного обязательного набора для этого решения выпуска нет. Это консервативная граница первой версии; независимые последовательные волны выпуска одного MO потребуют отдельного развития реестра.

## Правила прослеживаемости

1. Факт — только положительные строки проведённых основных готовых изделий данного MO в производственном карантине. Сохраняются stock.move/stock.move.line, company, product, lot/serial, owner, package, первоначальное назначение. Побочные продукты не включаются.
2. Обязательный набор QCP берётся из существующего snapshot quality_quarantine_point_ids, не из текущей изменяемой настройки продукта.
3. Для каждого lot необходим полный набор обязательных QC; размер каждой матрицы должен точно покрывать соответствующую фактическую выработку. Незавершённая QC, незавершённая строка, неверная структура, неполные ЗВТ, лишняя/отсутствующая QC или неоднозначный источник удерживают решение без движения.
4. Serial: одна физическая единица, одна подтверждённая serial/lot запись в источнике и одна строка в каждой обязательной QC этого serial. Изделие годно только при PASS всех его проверок. Нельзя распределять пять строк общей матрицы по пяти серийным номерам по порядку.
5. Lot / без tracking, одна обязательная матрица: законченная матрица даёт точные количества PASS и FAIL внутри этой партии. Частичный выпуск допускается только из однозначной фактической строки источника. При разных owner/package/нескольких строках без привязки к изделию частичный выбор источника запрещён.
6. Lot / без tracking, несколько обязательных матриц: все PASS допускают полный выпуск. Смешанные результаты без устойчивого unit ID не объединяются по sample_number; частичного выпуска нет. Исходные количества каждой QC остаются доступны, но фиктивное суммарное число физических годных изделий не вычисляется.
7. Для частичного пути требуется выделенный ключ карантинного источника. Если тот же product/lot/owner/package в этом карантине использовался и другим фактическим выпуском, первая версия не предполагает физическую раздельность таких изделий и удерживает частичное решение. Полный PASS продолжает использовать существующий полный путь.
8. Будущее развитие: самостоятельная физическая unit-запись (внутренний ID/QR), обязательная явная привязка к фактическому источнику и к строкам всех операций, запрет изменения использованных привязок. Сейчас эти идентификаторы не создаются и не подменяются порядковыми номерами.

## Изменения моделей и методов

- Новый production_release.py: изолированное расширение mrp.production, признак включения/snapshot и частный обработчик решения после существующего _quality_release_if_passed. Для остальных MO вызывается прежний обработчик.
- Новый чистый планировщик по фактам источников/QC: точное покрытие партий, serial identity, завершённость, доказанные годные/брак/неопределённость, распределение по исходным строкам. Без ORM и складских побочных действий; отдельные исполняемые unit-тесты.
- Новый неизменяемый quality.production.disposition: один snapshot на MO (SQL UNIQUE), ссылки на исходные QC, полная матрица результатов/идентичностей, фактические количества, причина удержания и проведённые release moves. Складские документы и результаты QC не переписываются.
- Полный PASS: существующий _quality_complete_release для полного количества.
- Частичный путь: тот же единственный заранее созданный release move; уменьшается только его непроведённое количество до доказанного годного, создаются только соответствующие фактические строки, проводится стандартным Stock API под существующим неприсылаемым извне quarantine token. Исходный готовый stock.move и его количество не меняются. Уникальность quality_held_move_id сохраняется.
- Поскольку первое решение окончательно для завершённого набора QC, повторные callback/клики не создают второго движения: блокировка MO, перечитывание источников и release moves, UNIQUE snapshot, выполнение и аудит в одной транзакции. Параллельный конфликт должен проходить обычный retry Odoo.
- 5 = 3 PASS + 2 FAIL: производственный приход остаётся 5 в карантин; внутренний release проводится на 3; quant карантина остаётся 2. QC остаётся FAIL, история пяти образцов сохранена.
- Полный FAIL: release move остаётся draft, складских движений нет; существующий техсовет целой производственной партии сохраняется.
- После частичного выпуска старый техсовет не должен принять/списать исходные 5 вместо остатка 2: его существующие проверки draft-состояния и точного количества сохраняются. Частичные решения техсовета над остатком относятся к развитию C, не обходятся в B.
- UI: стандартная форма MO, отдельный smart button «Розподіл ВТК», read-only snapshot, количества и связанные документы. Никакого нового интерфейса Shop Floor.
- Права: тот же автоматический сервис выпуска после штатного завершения QC, существующие права ВТК и Stock; новых групп и ручного универсального складского RPC нет. Публичные записи snapshot/изменение защищённых полей запрещены; чтение ограничено компаниями.

| ID | Сценарий | Ожидается |
|---|---|---|
| B01 | Lot, 5/5 PASS, одна обязательная QC | 5 разрешено, 0 карантин |
| B02 | Lot, 3 PASS + 2 FAIL | 3 разрешено, 2 карантин, исходная QC FAIL |
| B03 | Lot, 0 PASS + 5 FAIL | 0 разрешено, 5 карантин |
| B04 | 3 PASS + 1 FAIL + 1 pending | 0 выпуска; после завершения последнего образца — только доказанные годные |
| B05 | Повторное завершение/перезагрузка/повторный callback | Те же move IDs, количества и единственный snapshot |
| B06 | Две обязательные операции без unit ID, смешанные результаты | 0 выпуска, вся партия удержана; sample_number не объединяется |
| B07 | Две обязательные операции без unit ID, все PASS | Полный выпуск допустим |
| B08 | Две различные партии | Проверки, фактические строки и количества не переносятся между lot; итоговые движения сохраняют lot |
| B09 | Неполный набор QC по одной из партий | Выпуск атомарного решения MO запрещён |
| B10 | Serial, явные отдельные QC на каждый serial, 3 годных/2 брака | Движутся только три конкретных подтверждённых serial |

| B12 | Несовпадение automatic lot и фактического lot, дубли QC, неверный sample count | Удержание, 0 движений |

| B15 | Прямые create/write snapshot, подмена флага существующего MO | Отказ до изменения остатков |

Чистые тесты планировщика запускаются локально. Enterprise ORM-тесты без отдельной лицензированной базы остаются BLOCKED, не запускаются разрушительно на общей staging. Все доступные браузерные сценарии выполняются на отдельных AQC-B-* записях. Неподдержанные физические конфигурации проверяются на безопасный отказ, а не считаются рабочим частичным выпуском.
